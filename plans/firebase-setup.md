# Firebase setup for Fairvoice Android notifications

1. Using an organization-managed Google account, create a Fairvoice staging project in the Firebase console. Use a separate Firebase project and sender identity for production. [Firebase Android setup](https://firebase.google.com/docs/android/setup)
2. Under **Project settings → Your apps → Add app → Android**, enter the variant’s exact application ID. The current Fairvoice flavor uses `com.msgvox.mobile.fairvoice`. If staging introduces an application ID suffix, register the suffixed ID in the staging project. Download `google-services.json` and supply it to the matching Android build variant. [Fairvoice build configuration](../OTHER_PROJECTS/cht-android/build.gradle) · [Register an Android app](https://firebase.google.com/docs/android/setup)
3. Enable the **Firebase Cloud Messaging API** in the associated Google Cloud project. Grant a dedicated Core runtime identity the **Firebase Cloud Messaging API Admin** role on that project. Configure Core with the matching project ID and Application Default Credentials. Prefer a workload identity. If a credential file is necessary, mount it as a server-side secret and keep it out of source control and the APK. [FCM HTTP v1 authorization](https://firebase.google.com/docs/cloud-messaging/auth-server)
4. After implementing the [Core](fairvoice-cht-core-fcm.md) and [Android](cht-android-fcm.md) plans, install the staging build on a Google Play services device or emulator, sign in, grant notification permission, and enable sending for the staging pilot. Send a real CHT data message from another eligible account. With the recipient app open, check the alert, badge, and current screen. Background the app, send another message, and tap the sender-named notification to verify the conversation. A console test notification alone does not exercise Core registration, data-only delivery, or tap routing. [Firebase Android receive behavior](https://firebase.google.com/docs/cloud-messaging/android/receive-messages)
